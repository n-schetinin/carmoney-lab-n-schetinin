# Intent MILEAGE: «пробег не больше 400 000 км, иначе решение review»

Лог интервью: `docs/intent/grill_MILEAGE.md`. Метки источников: «интервью: формулировка
задачи» и «интервью: ответ, вопрос N» — по логу; «код: <файл>» — текущее поведение
кодовой базы.

## 1. Замысел

Добавить в расчёт решения по заявке проверку пробега автомобиля: пробег не больше
400 000 км — решение остаётся прежним, по LTV; пробег больше 400 000 км — итоговое
решение `review` (интервью: формулировка задачи).

## 2. Зачем

Сегодня решение по заявке зависит только от LTV, пробег в нём не участвует
(код: backend/src/Domain/DecisionEngine.php): даже предельный для валидации пробег
не мешает получить `approve` при низком LTV. Правило закрывает этот пробел:
завышенный пробег больше не проходит мимо решения — такие заявки уходят в `review`
(интервью: формулировка задачи).

## 3. Constraints

- **Порог 400 000 км, граница включительная:** ровно 400 000 — допустимо, правило
  срабатывает с 400 001 км (интервью: формулировка «не больше 400 000»; ответ,
  вопрос 2).
- **Итог при срабатывании — `review`, безусловно:** каким бы ни был вердикт по LTV —
  `approve` (интервью: формулировка «иначе решение review») или `reject`
  (интервью: ответ, вопрос 1), — при пробеге выше порога итог `review`.
- **Пробег в пределах порога решение не меняет** — работает только расчёт по LTV
  (интервью: формулировка задачи; код: backend/src/Domain/DecisionEngine.php).
- **Ввод пробега не меняется:** поле обязательно, целое, неотрицательное,
  0–500 000 км; отсутствие или выход за диапазон — ошибка валидации (422),
  решение не вычисляется (код: backend/src/Domain/ApplicationValidator.php).
- **Зона действия правила — 400 001–500 000 км:** выше 500 000 заявка до решения
  не доходит (422), потолок валидации не понижается — иначе у правила не останется
  зоны действия (код: backend/src/Domain/ApplicationValidator.php; интервью:
  формулировка «иначе review», а не «ошибка ввода»).
- **`approved_limit` при `review` — 0**, как сегодня для любого решения, отличного
  от `approve`; правило не вводит свой расчёт лимита
  (код: backend/src/Domain/AssessmentService.php).
- **Контракт ответа не меняется:** `decision` остаётся одной из трёх строк
  `approve|review|reject`, поле с причинами решения не добавляется
  (интервью: ответ, вопрос 3; код: backend/src/Domain/DecisionEngine.php).
- **Сохранённые заявки и seed не пересчитываются:** правило действует только на
  новые оценки (интервью: ответ, вопрос 4).

## 4. Open questions

- Приоритет при столкновении с `reject` — **закрыт**: заказчик, интервью, вопрос 1
  (итог `review`).
- Граница 400 000 км — **закрыт**: заказчик, интервью, вопрос 2 (400 000 проходит).
- Причины `review` в ответе API — **закрыт**: заказчик, интервью, вопрос 3
  (не добавляются).
- Пересчёт сохранённых решений — **закрыт**: заказчик, интервью, вопрос 4
  (не пересчитываются).
- Пробег не указан / вне 0–500 000 — **закрыт**: поведение не меняется
  (код: backend/src/Domain/ApplicationValidator.php; озвучено в интервью до
  вопросов, возражений не было).

Открытых вопросов нет: сверка Constraints с исходной формулировкой задачи
(«добавить в расчёт решения по заявке проверку — пробег авто не больше 400 000 км,
иначе решение review») расхождений не выявила.

## 5. Не входит

- Поле с причинами решения в ответе API (интервью: ответ, вопрос 3).
- Пересчёт уже сохранённых решений, включая seed (интервью: ответ, вопрос 4).
- Изменение порогов и формулы LTV — формулировка задачи их не касается
  (код: backend/src/Domain/DecisionEngine.php).
- Понижение потолка валидации пробега 500 000 км
  (код: backend/src/Domain/ApplicationValidator.php).
- Фронтенд и БД: форма уже отправляет пробег, БД уже хранит
  (код: frontend/app.js; код: db/schema.sql).
- Расчёт лимита по возрасту автомобиля — отдельная задача LOAN-12
  (код: backend/config/rules.php).
- Фикс расхождения комментария и кода по границе `approve` — соседняя проблема,
  к задаче не относится (код: backend/src/Domain/DecisionEngine.php).
