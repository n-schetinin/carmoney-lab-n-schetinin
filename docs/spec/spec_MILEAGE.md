# Спека MILEAGE: пробег не больше 400 000 км, иначе решение review

Основание: `docs/intent/intent_MILEAGE.md` (замысел, Constraints, «Не входит»)
и `docs/intent/grill_MILEAGE.md` (лог интервью). Метки источников — как в intent:
«интервью: формулировка задачи» и «интервью: ответ, вопрос N» — по логу;
«код: <файл>» — текущее поведение кодовой базы. Здесь фиксируется, что считается
сделанным; как реализовывать — в `docs/plan/plan_MILEAGE.md`.

## Входит / не входит

**Входит** — поведение расчёта решения новой оценки заявки:

- правило пробега: пробег больше 400 000 км — итоговое решение `review`
  (интервью: формулировка задачи);
- граница правила: ровно 400 000 км допустимо, срабатывает с 400 001 км
  (интервью: ответ, вопрос 2);
- перезапись любого вердикта по LTV, включая `reject` (интервью: ответ, вопрос 1);
- `approved_limit` при таком `review` — 0 по действующей логике лимита
  (код: backend/src/Domain/AssessmentService.php:39);
- инвариант: ввод пробега не меняется — обязательное поле, диапазон 0–500 000 км,
  при отсутствии или вне диапазона ошибка валидации 422, решение не вычисляется
  (код: backend/src/Domain/ApplicationValidator.php:43–46);
- инвариант: контракт ответа не меняется — `decision` остаётся одной из трёх строк,
  поле с причинами решения не добавляется (интервью: ответ, вопрос 3);
- инвариант: зона действия правила — только новые оценки; сохранённые заявки
  и seed не пересчитываются (интервью: ответ, вопрос 4).

**Не входит** (все пункты — из intent §5):

- поле с причинами решения в ответе API (интервью: ответ, вопрос 3);
- пересчёт уже сохранённых решений, включая seed (интервью: ответ, вопрос 4);
- изменение порогов и формулы LTV (код: backend/src/Domain/DecisionEngine.php);
- понижение потолка валидации пробега 500 000 км
  (код: backend/src/Domain/ApplicationValidator.php);
- фронтенд и БД: форма уже отправляет пробег, БД уже хранит
  (код: frontend/app.js; код: db/schema.sql);
- расчёт лимита по возрасту автомобиля — отдельная задача LOAN-12
  (код: backend/config/rules.php);
- фикс расхождения комментария и кода по границе `approve`
  (код: backend/src/Domain/DecisionEngine.php).

## Требования

- **REQ-MILEAGE-01.** Правило пробега срабатывает при пробеге больше 400 000 км
  и не срабатывает при 400 000 км и меньше. — интервью: формулировка задачи
  («не больше 400 000 км»); интервью: ответ, вопрос 2 (400 000 проходит,
  зона срабатывания — с 400 001 км).
- **REQ-MILEAGE-02.** При пробеге 400 000 км и меньше решение заявки совпадает
  с решением по действующим порогам LTV (`approve` / `review` / `reject`);
  правило пробега его не меняет. — интервью: формулировка задачи; код:
  backend/src/Domain/DecisionEngine.php (сегодня решение зависит только от LTV).
- **REQ-MILEAGE-03.** При пробеге больше 400 000 км вердикт `approve` по LTV
  не остаётся: итоговое решение — `review`. — интервью: формулировка задачи
  («иначе решение review»).
- **REQ-MILEAGE-04.** При пробеге больше 400 000 км вердикт `reject` по LTV
  заменяется на `review`: итоговое решение — `review`, не `reject`. —
  интервью: ответ, вопрос 1.
- **REQ-MILEAGE-05.** При итоговом решении `review` поле `approved_limit` = 0;
  правило пробега не вводит собственного расчёта лимита (лимит равен запрошенной
  сумме только при `approve`, иначе 0). — код:
  backend/src/Domain/AssessmentService.php:39.
- **REQ-MILEAGE-06.** Контракт ответа оценки не меняется: `decision` — одна из
  трёх строк `approve` / `review` / `reject`; поле с причинами решения в ответ
  не добавляется. — интервью: ответ, вопрос 3; код:
  backend/src/Domain/DecisionEngine.php:16–18.
- **REQ-MILEAGE-07.** Если ключа `mileage` нет или его значение `null`, оценка
  завершается ошибкой валидации: ответ HTTP 422 с ошибкой по полю `mileage`,
  решение не вычисляется. — код: backend/src/Domain/ApplicationValidator.php:43–46
  (`?? -1`); код: backend/src/Http/ApplicationController.php:30.
- **REQ-MILEAGE-08.** Если пробег меньше 0 или больше 500 000 км, оценка
  завершается ошибкой валидации: ответ HTTP 422 с ошибкой по полю `mileage`,
  решение не вычисляется. — код: backend/src/Domain/ApplicationValidator.php:44–45;
  код: backend/config/rules.php:23.
- **REQ-MILEAGE-09.** Потолок валидации 500 000 км не понижается: заявки
  с пробегом 400 001–500 000 км проходят валидацию и доходят до расчёта решения —
  это зона действия правила. — интервью: формулировка задачи («иначе review»,
  а не «ошибка ввода»); код: backend/src/Domain/ApplicationValidator.php:44.
- **REQ-MILEAGE-10.** Правило применяется только при расчёте новых оценок:
  решения уже сохранённых заявок (включая seed) не пересчитываются. —
  интервью: ответ, вопрос 4.

## Критерии приёмки

Точка проверки — `POST /api/ltv`, расчёт решения без сохранения заявки (код:
backend/src/Http/ApplicationController.php:53–69); `POST /api/applications`
выполняет тот же расчёт и по этим критериям эквивалентен.

Базовый набор полей заявки — фикстуры действующего теста
(tests/Unit/AssessmentServiceTest.php:33–43): `vin` XTA21099998765432,
`year` = текущий год − 4, `market_value` 900000, `term_months` 24; в критериях
меняются только `mileage` и `requested_amount`. Зоны LTV — пороги 60.0 / 85.0
(код: backend/config/rules.php:43–46; код: backend/src/Domain/DecisionEngine.php:32–40):
`requested_amount` 450000 → LTV 50.0, зона `approve`; 675000 → 75.0, зона `review`;
855000 → 95.0, зона `reject` (фикстуры tests/Unit/AssessmentServiceTest.php:47, 57, 66).
Граничные значения 399999 / 400000 / 400001 — конвенция спеки «на пороге и рядом
с ним» (docs/spec/README.md:9); порог 400 000 — интервью: формулировка задачи.
HTTP 422 — код: backend/src/Http/ApplicationController.php:30.

- **AC-MILEAGE-01** (REQ-MILEAGE-01, REQ-MILEAGE-02). Given: пробег 399999 км,
  LTV 50 (зона `approve`). When: заявка отправлена на оценку. Then:
  `decision` = `approve`, `approved_limit` = 450000 — порог не сработал,
  решение как по LTV.
- **AC-MILEAGE-02** (REQ-MILEAGE-01, REQ-MILEAGE-02). Given: пробег 400000 км,
  LTV 50. When: оценка. Then: `decision` = `approve`, `approved_limit` = 450000 —
  ровно на пороге правило не срабатывает (граница включительная).
- **AC-MILEAGE-03** (REQ-MILEAGE-01, REQ-MILEAGE-03, REQ-MILEAGE-05). Given:
  пробег 400001 км, LTV 50. When: оценка. Then: `decision` = `review`,
  `approved_limit` = 0 — сразу за порогом вердикт `approve` заменён на `review`.
- **AC-MILEAGE-04** (REQ-MILEAGE-04, REQ-MILEAGE-05). Given: пробег 400001 км,
  LTV 95 (зона `reject`). When: оценка. Then: `decision` = `review` (не `reject`),
  `approved_limit` = 0.
- **AC-MILEAGE-05** (REQ-MILEAGE-02). Given: пробег 399999 км, LTV 95. When:
  оценка. Then: `decision` = `reject`, `approved_limit` = 0 — при пробеге в норме
  правило решение не меняет.
- **AC-MILEAGE-06** (REQ-MILEAGE-02). Given: пробег 400000 км, LTV 75 (зона
  `review`). When: оценка. Then: `decision` = `review`, `approved_limit` = 0 —
  третья зона LTV на границе: решение как по LTV, без влияния правила.
- **AC-MILEAGE-07** (REQ-MILEAGE-03, REQ-MILEAGE-05, REQ-MILEAGE-09). Given:
  пробег 500000 км — потолок валидации (код: backend/config/rules.php:23),
  LTV 50. When: оценка. Then: `decision` = `review`, `approved_limit` = 0 —
  верхняя граница зоны действия правила, заявка до решения дошла.
- **AC-MILEAGE-08** (REQ-MILEAGE-08, REQ-MILEAGE-09). Given: пробег 500001 км.
  When: заявка отправлена на оценку. Then: HTTP 422, в `errors` есть ключ
  `mileage`, полей `decision` и `ltv` в ответе нет — сразу за потолком валидации
  заявка до решения не доходит, потолок не понижен.
- **AC-MILEAGE-09** (REQ-MILEAGE-02, REQ-MILEAGE-08). Given: пробег 0 км —
  нижняя граница диапазона валидации (код:
  backend/src/Domain/ApplicationValidator.php:44), LTV 50. When: оценка. Then:
  `decision` = `approve`, `approved_limit` = 450000 — нижняя граница валидна,
  доходит до решения.
- **AC-MILEAGE-10** (REQ-MILEAGE-08). Given: пробег −1 км — значение меньше
  нижней границы; тот же код-путь сравнения, что у отсутствующего поля (код:
  backend/src/Domain/ApplicationValidator.php:43–44). When: оценка. Then:
  HTTP 422, в `errors` есть ключ `mileage`, решение не вычислялось.
- **AC-MILEAGE-11** (REQ-MILEAGE-07). Два случая: (а) ключ `mileage` в заявке
  отсутствует; (б) `mileage` = `null` — тот же код-путь через `?? -1` (код:
  backend/src/Domain/ApplicationValidator.php:43). When: заявка отправлена
  на оценку. Then: HTTP 422, в `errors` есть ключ `mileage`, решение
  не вычислялось — пустой или неизвестный пробег остаётся ошибкой валидации,
  а не `review`.
- **AC-MILEAGE-12** (REQ-MILEAGE-06). Given: заявка, прошедшая валидацию
  (например, из AC-MILEAGE-01 или AC-MILEAGE-03). When: оценка. Then: в ответе
  `decision` — одна из трёх строк `approve` / `review` / `reject`; состав
  остальных полей прежний (`vehicle_age`, `ltv`, `approved_limit`; код:
  backend/src/Http/ApplicationController.php:64–69), поле с причинами решения
  в ответе нет.
- **AC-MILEAGE-13** (REQ-MILEAGE-10). Given: заявка (пробег 450000 км — внутри
  зоны действия правила, LTV 95 — фикстура reject-зоны) сохранена до внедрения
  правила с решением `reject`. When: после внедрения запрошена карточка
  `GET /api/applications/{id}` (или список). Then: решение в ответе — прежний
  `reject`, пересчёта нет; данные seed не переписываются (интервью: ответ,
  вопрос 4; код: backend/src/Http/ApplicationController.php:72–89 — карточка
  и список читают сохранённое; db/seed.sql:57–81).

AC-MILEAGE-01…05, 07, 11 совпадают со списком тестов плана
(docs/plan/plan_MILEAGE.md, раздел «Тесты»); AC-MILEAGE-06, 08–10, 12–13
фиксируют неизменное поведение (третья зона LTV на границе, ввод, контракт,
хранилище). Чем их покрывать — существующими тестами или расширением списка
в плане; реализация — не предмет спеки.
